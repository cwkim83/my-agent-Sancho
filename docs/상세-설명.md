## 실행

1. 준비: Node.js 18 이상 · Claude 유료 요금제(Pro·Max·Team) · 이 PC 에서 Claude Code 로그인
2. `start.bat` 을 더블클릭 → 브라우저에서 `http://127.0.0.1:8790` (이 PC 안에서만 열립니다). 서버는 감시자(`supervisor.js`)가 켜고 지켜봅니다 (아래 "8편 안전장치")
3. 처음 열면 관리자 계정을 만듭니다. 점검은 `node selftest.js`

- 외부 패키지가 없습니다(Node.js 내장 기능만). 데이터는 `data/` 폴더의 파일이고 git 에 올리지 않습니다.
- 휴대폰·밖에서 쓰기, claude.ai 커넥터, 목소리는 아래 "9편"을 보세요. 모두 기본이 꺼짐이고, 무엇이 밖으로 나가는지는 "개인정보가 밖으로 나가는 지점" 표에 모아 두었습니다.

## 10편 — 비서가 배운 것을 쌓기: 위키 · 스킬 (채팅 왼쪽 "위키"·"스킬" 칸)

| 말 | 일어나는 일 | 어디에 남나 |
|---|---|---|
| "○○ 조사해서 **위키에 저장해**" | 비서가 알게 된 내용을 주제 하나당 문서 하나로 정리해 저장 | `data/wiki/<주제>.md` |
| 나중에 관련 질문 | 비서가 답하기 전에 위키부터 찾아 참고하고 "(위키 「주제」 참고)" 라고 밝힘 | (위 문서를 읽음) |
| "**방금 한 일 스킬로 저장해**" | 방금 대화의 절차(이름·언제 쓰는지·순서)를 스킬로 저장. 다음 대화부터 비서가 요청에 맞으면 그 문서를 먼저 읽고 따름 | `data/.claude/skills/<이름>/SKILL.md` |

- 채팅 왼쪽의 **위키**·**스킬** 칸은 평소 제목 한 줄로 접혀 있고, 누르면 목록이 펼쳐집니다. 이름을 누르면 내용을 열어 보고, ✕ 로 지웁니다 (지우기 전에 한 번 더 묻습니다).
- **위키**는 모두가 함께 씁니다(누구나 보고 지울 수 있어요). 위키 내용은 **참고 자료일 뿐 지시가 아닙니다** — 웹에서 가져온 글이 섞여도 비서가 그 안의 "~하라"를 따르지 않게 지침에 적어 두었습니다.
- **스킬**은 모든 사람의 비서에게 적용되므로 **관리자만 저장·삭제**합니다 (일반 사용자는 목록만 볼 수 있어요). 기본 스킬(platform·wbs·mail·office-docs·approval·okr)은 칸에 나오지 않고 덮어쓸 수도 없습니다. 최대 30개.
- 비서는 `.claude` 폴더를 고칠 수 없습니다(그대로 유지). 그래서 스킬은 비서가 `users/<아이디>/skill-draft.md` 에 **초안만** 놓으면, 말이 끝난 뒤 **서버가 검사해서** 저장합니다 (결재 "기안서 써 줘"와 같은 방식). 서버가 지키는 것: ① 주인이 그 말에서 직접 "스킬 … 저장"이라고 했을 때만(웹 페이지·파일 속 글이 시켜서는 안 만들어지고 🔔 주의 알림이 남음) ② 관리자만 ③ 이름은 한글·영문·숫자·하이픈 40자까지 ④ 앞머리는 `name`·`description` 두 줄만 남김(허용 도구·훅 같은 칸은 버림) ⑤ 본문 8000자까지.
- 왜 서버가 목록을 알려 주나: 비서의 Claude Code 는 개발용 기능을 끄고(격리) 돌아서 스킬을 스스로 찾지 못합니다. 그래서 서버가 실행할 때마다 "저장된 스킬 이름 — 언제 쓰는지"와 위키 문서 이름을 알려 주고, 비서가 맞는 것을 읽습니다.
- 점검: `node selftest.js` 의 `runKb` 26개 항목 (위키 저장·목록·열기·삭제와 폴더 밖으로 나가는 이름 막기, 스킬 초안 검사(훅 끼워 넣기·기본 스킬 덮어쓰기·시키지 않은 초안·일반 사용자·30개 한도·묵은 초안), 두뇌에 알리는 글).
- 한계: 한 사람이 한 번에 하나의 스킬 초안만 놓을 수 있고(두 대화를 동시에 돌리면 한쪽이 지워질 수 있어요), 위키는 파일 이름으로만 찾습니다(내용 검색은 비서의 Grep). 필요해지면 늘립니다.

### 지식노트 메뉴 (왼쪽 메뉴 "지식노트", `public/m/knowledge.html` · 계산은 `public/m/knowledge-calc.js`)

그림 라이브러리 없이 캔버스(2D)로 직접 그립니다. 위쪽 단추로 두 화면을 오갑니다.

| 화면 | 무엇을 보여 주나 | 조작 |
|---|---|---|
| 🗺 **지식 지도** (처음 화면) | 프로젝트(파랑)·할 일(초록)·회의(보라)·결재(주황)·위키(청록)·사람(분홍)을 **점**으로, 서로 **언급하면 선**으로 잇습니다. 진한 회색 선은 자료가 직접 가리키는 관계(할 일→프로젝트, 회의→참석자, 결재→기안자·결재선), 연보라 선은 글에서 이름이 나온 관계(위키 본문이 프로젝트 이름을 말함 등) | 끌어서 점 옮기기(옮긴 점은 고정, 더블클릭으로 풀기) · 빈 곳 끌면 이동 · 휠·두 손가락·＋－⤢ 로 확대 · 점을 누르면 **미리보기**(내용·이어진 점·"열기 →"로 그 메뉴로 이동) · 점 찾기 · 위쪽 색 단추로 종류 숨기기 |
| 🧠 **뇌 그래프** | 기억·위키·스킬·대화·예약을 **하나의 그래프**로. 가운데 "산초" → 다섯 칸 → 항목. 기억·대화 제목·예약 지시문이 위키·스킬 이름을 말하면 선으로 이음 | 기본은 **오브**: 링·호·입자가 숨 쉬듯 움직이고, 비서가 **생각하면 빨라지고**(금빛) **말하면 출렁입니다**(물결). 오브 아래 입력칸에서 비서에게 바로 말을 걸 수 있고(같은 비서·대화 목록에 남음), "✦ 그래프" 단추로 그래프와 전환 |

- **점이 많아도 느려지지 않게**: 그래프는 "✦ 그래프"를 누를 때만 만들고 그립니다(오브로 돌아가면 그리기를 끔). 점은 종류마다 개수를 자르고(지식 지도: 할 일 300·회의 120·결재 120·위키 60 …, 뇌 그래프: 기억 120·위키 120·대화 100·예약 40·스킬 30 — 잘린 개수는 위쪽에 알려 줘요), 배치 계산은 한 프레임에 8ms 만 쓰며, 점 배치가 끝나면 끌거나 확대할 때만 다시 그립니다. 이름표는 겹치지 않는 것만 그려서 점이 몰려도 읽힙니다.
- **내 것만 보입니다**: 화면이 읽는 주소는 기존 것(프로젝트·할 일·회의 `db`, 결재 `/api/approvals`, 위키·스킬, 내 기억·대화·예약)이라, 결재 문서는 내가 볼 수 있는 것만, 기억·대화·예약은 내 것만 나옵니다.
- 언급 찾기는 "이름 글자가 글 안에 들어 있나"(띄어쓰기·하이픈 무시)뿐이고, 점의 30% 넘게 나오는 흔한 이름은 선을 긋지 않습니다. 점이 수천 개가 되면 형태소 분석이나 색인이 필요해요.
- 점검: `node selftest.js` 의 `runKnowledgeCalc`(서버 없이 `SELFTEST_ONLY=knowledge node selftest.js` 로 빨리) · `runKnowledge`.

### 워크플로 메뉴 (왼쪽 메뉴 "워크플로", `public/m/workflow.html` · 규칙은 `public/m/workflow-calc.js` · 실행은 `workflow.js` · 자료는 `data/db/workflows.json`·`workflowruns.json`) — 관리자만

n8n 처럼 **노드를 이어 붙여** 반복 업무를 자동화합니다. 위쪽 팔레트에서 노드를 더하고, 캔버스에서 끌어 놓고, 오른쪽 점(●)에서 끌어 다음 노드에 잇습니다(조건 나누기는 "참"·"거짓" 점이 따로). 노드를 누르면 오른쪽에 설정 패널이 열리고, 바꾸는 즉시 저장됩니다.

| ▶ 수동 시작 · ⏰ 매일 시각 · 🔁 N분마다 | 시작점. ▶ 실행은 시작 노드부터, 자동 실행은 시계 노드가 정한 때에 | 시각 / 분 |

- **같은 와이파이 직접 접속은 http(암호화 없음)입니다.** 터널만 쓸 때는 `0.0.0.0` 이 꼭 필요하지 않지만 스위치 하나로 단순하게 두었어요. 처음 켤 때 윈도우 방화벽이 물으면, 직접 접속할 일이 없으면 "취소"해도 터널은 돼요.
- **점검**: `node selftest.js` 가 9편까지 모두 검사합니다. 한 부분만 빨리 볼 때는 `SELFTEST_ONLY=access`(외부 접속) · `connector`(커넥터) · `voice`(목소리). 마이크·스피커·실제 휴대폰은 사람이 확인합니다.

### 1. 휴대폰 화면과 홈 화면에 추가 (PWA)

- **좁은 화면(폭 800px 이하)**: 왼쪽 메뉴는 위쪽 ☰ 로 접히고(바깥을 누르면 닫힘), 아래 탭 **채팅 · 대시보드 · 일정** 으로 한 칸씩 봅니다. 채팅 칸의 왼쪽 목록(대화·예약·기억)은 "📂 대화 목록"으로 엽니다. 일정은 월 보기가 점·색 줄로 줄고, 날짜를 누르면 그 주의 세로 목록이 열리며, "＋ 추가"로 일정을 넣습니다. 넓은 화면은 예전 그대로입니다.
- **홈 화면에 추가**: `public/manifest.webmanifest`(이름 "Sancho", 주소창 없이 열리는 `standalone`)와 아이콘 192·512(`public/icons/`, `node make-icons.js` 로 다시 만듦)가 있습니다. 이 PC 에서는 로그인 전에도 받아지고, 밖에서는 접속 토큰이 있어야 받아집니다(그래서 manifest 는 쿠키를 같이 보내도록 `crossorigin="use-credentials"`). 홈 화면에 추가는 `https://`(터널) 또는 `127.0.0.1` 주소에서만 됩니다.
- 개발 중에는 Claude 데스크톱의 Browser 패널 크기를 휴대폰(375×812)으로 바꿔 확인합니다.

### 2. 외부 접속 — 밖(휴대폰)에서 안전하게 열기 (설정 › 외부 접속 · `tunnel.js`)

- **기본은 꺼짐**: 서버는 `127.0.0.1`(이 PC 안)에서만 열립니다. 설정 › **외부 접속**에서 **접속 토큰을 만들고** 스위치를 켜면 `0.0.0.0` 으로 열립니다. 껐다 켜도 설정이 이어지고, 끄면 바로 다시 `127.0.0.1` 로만 열립니다.
- **두 겹**: 밖에서 온 요청은 **접속 토큰이 없으면 로그인 화면조차 보이지 않고**(화면·API·manifest·아이콘·공유 링크 전부 403, 막힌 화면에는 앱 이름도 없음), 그다음에 아이디·비밀번호로 로그인합니다. 토큰은 처음 한 번 입력 칸(또는 주소 뒤 `?t=토큰` — 맞으면 바로 쿠키로 바꾸고 주소에서 지움)으로 넣고, 쿠키에는 토큰이 아니라 그 해시가 들어갑니다. 틀린 토큰을 11번 넘게 넣으면 그 IP 는 10분 잠깁니다. 토큰을 새로 만들면 예전 토큰·쿠키는 바로 못 씁니다.
- **켜면 위험 스위치가 자동으로 꺼집니다**: "명령 실행"·"자기 수정"은 외부 접속을 켜는 순간 꺼지고, 켜 둔 채 다시 켜려면 경고를 한 번 더 확인해야 합니다(서버도 확인 표시 없이는 409 로 거절). 채팅 입력창에는 🌐 외부 표시가 뜹니다.
- **위험한 일은 이 PC 에서만**: 밖에서는 (토큰·로그인이 맞아도) 권한·외부 접속·토큰 변경, 서버 다시 시작, "열기"(이 PC 의 프로그램으로 파일 열기)를 할 수 없고, 토큰 값도 볼 수 없습니다. 토큰과 비밀번호가 새어도 밖에서 이 PC 를 조종하지 못하게 한 것입니다.
- **토큰은 가려서만**: 값은 `data/settings.json`(비서도 못 읽음)에만 있고 화면에는 ●●● 로만 보입니다. [복사]는 클립보드로만 가져가고(이 PC 에서만), [10초 보기]는 10초 뒤 다시 가립니다.
- **"밖에서 온 요청"을 가리는 법**: Cloudflare 터널은 이 PC 안에서 서버에 접속하므로 접속한 쪽 주소만으로는 알 수 없습니다. 그래서 ① 접속한 쪽이 이 PC 가 아님 ② Host 가 127.0.0.1·localhost 가 아님 ③ 프록시가 붙이는 머리글(cf-*, x-forwarded-* 등) 중 하나라도 있으면 밖에서 온 것으로 봅니다. 외부 접속이 꺼져 있으면 이런 요청은 토큰이 있어도 모두 막힙니다.
- **Cloudflare 터널(`node tunnel.js`)**: 안에서 `cloudflared tunnel --url http://127.0.0.1:8790` 을 켜고, 나온 주소를 화면과 `data/tunnel.json` 에 알려 줍니다. 끄기는 그 창에서 Ctrl+C 또는 `node tunnel.js stop`. cloudflared 가 없으면 `winget install --id Cloudflare.cloudflared`.
  - 이 PC 에 다른 터널 설정(`~/.cloudflared/config.yml`)이 있으면, `--url` 만으로 만든 임시 터널이 그 파일의 규칙을 따라 **모든 요청이 404** 가 됩니다(내 서버까지 오지도 않음). 그래서 `tunnel.js` 는 빈 파일 `data/tunnel-quick.yml` 을 `--config` 로 지정해 그 파일을 읽지 않게 합니다. 기존 설정 파일은 건드리지 않습니다.

### 3. 커넥터 — claude.ai 에서 이 비서를 "읽기 전용"으로 부르기 (설정 › 커넥터 · `mcp.js`)

- **무엇**: claude.ai 의 **커스텀 커넥터**로 붙일 수 있는 `/mcp-<비밀 48자>` 창구입니다. MCP(Model Context Protocol)의 Streamable HTTP · JSON-RPC 2.0 이고 외부 패키지는 없습니다. 상태를 들고 있지 않아 세션이 없고 `POST` 만 받습니다(`GET`·`DELETE` 는 405). `initialize` · `ping` · `tools/list` · `tools/call` 만 압니다.
- **도구는 읽기 전용 5개뿐**: `get_today_events`(오늘 일정) · `get_week_events`(이번 주 월~일 일정) · `list_projects`(프로젝트 목록·진도율, WBS 가 있으면 WBS 기준 진도와 지연 수) · `get_delayed_wbs_tasks`(계획보다 10%p 넘게 뒤처진 WBS 작업 — WBS 화면의 "지연"과 같은 기준) · `get_my_tasks`(커넥터를 만든 사용자의 할 일). **쓰기·실행 도구는 없습니다.**
- **쓰기·실행을 못 넣는 구조**: 도구를 처리하는 `mcp.js` 에는 `require` 가 하나도 없습니다. 그래서 파일·네트워크·프로그램 실행을 할 수 없고, 서버가 건네주는 "읽기 함수"로 본 것만 돌려줍니다. selftest 가 도구 목록(정확히 5개, 모두 `readOnlyHint`)과 이 사실을 못박아 두어서, 비서가 "자기 수정"으로 도구를 더해도 검사를 통과하지 못합니다.
- **주소의 비밀**: 설정 › 커넥터 › [커넥터 주소 만들기]. [다시 만들기]를 누르면 옛 주소는 바로 무효입니다. 비밀은 무작위 영숫자 48자이고 `data/connector.json`(비서도 못 읽음)에만 있으며, 화면에는 ●●● 로만 보입니다([주소 복사]·[10초 보기]). 틀린 주소는 404, 11번 넘게 틀리면 그 IP 는 10분 잠깁니다. 다른 사이트의 Origin 을 단 요청은 막습니다.
- **외부 접속과의 관계**: 이 주소만은 접속 토큰 관문을 지나지 않고 주소 속 비밀이 그 몫을 합니다. 그래도 외부 접속이 꺼져 있으면 밖에서 온 요청은 이 주소도 막힙니다. claude.ai 가 부르려면 ① 외부 접속 켜기 ② 터널 켜기가 필요합니다.
- **이용 기록**: `data/logs/connector.jsonl` 에 시각·도구 이름·성공 여부만 남깁니다(없는 도구는 "(알 수 없는 도구)"). 설정 화면에서 최근 10건을 봅니다.
- **claude.ai 에 추가하기(각자 자기 계정에서)**: claude.ai › 설정 › 커넥터 › 커스텀 커넥터 추가 → 이름(예: Sancho)과 주소 `https://<터널 주소>/mcp-<비밀>` 를 붙여 넣습니다. 이 저장소는 그 과정을 대신하지 않습니다.

### 4. 목소리 — 말로 보내고, 답을 읽어 주기 (채팅 🎤·🔊 · 설정 › 목소리 · `public/m/voice.js`)

- **🎤 말해서 보내기**: 채팅 입력창의 🎤 를 누르고 한국어로 말하면(브라우저 음성 인식, `ko-KR`) 말하는 대로 입력창에 보이고, **말이 끊기면 자동으로 보냅니다.** 듣는 중에 다시 누르면 취소. 마이크가 막혔거나 없으면 위쪽 표시에 쉬운 이유가 뜹니다. 처음 쓸 때 말소리가 브라우저 회사 서버로 간다는 안내가 한 번 뜹니다.
- **"산초야" 호출 대기**(설정 › 목소리, **기본 꺼짐**): 켜면 마이크가 계속 듣다가 **"산초야"로 시작하는 말만** 받습니다.
  - 인식기가 이름을 다르게 적어도(산초·산쵸·잔초·산조야·샨초야·산추야·상초야·"산초 야"·Sancho) 소리가 비슷하면 받습니다. 소리 조각 단위로 거리를 재서, 비슷한 소리끼리의 틀림은 작게, 그 밖은 크게 셉니다. 소리가 한 글자 다른 말(산책·난초야·반초야·선초야)이나 말 중간에 낀 호출어는 받지 않습니다.
  - "산초야"만 말하고 쉬면 "네, 말씀하세요" 하고 다음 말을 명령으로 받습니다(8초).
  - 인식기가 시작되지 않으면(마이크를 다른 프로그램이 쓰는 중 등) 1·2·4·8초… 쉬며 다시 시도하고, 여섯 번 넘게 안 되면 그만두고 알립니다. 허용을 안 했거나 마이크가 없으면 바로 그만둡니다.
  - 이 설정은 이 브라우저(이 기기의 마이크)에만 저장되고, 켜 두는 동안 위쪽에 "👂 호출 대기"가 떠 있습니다.
- **답 읽어 주기**: 한국어 브라우저 목소리(`speechSynthesis`)로 읽습니다. 코드·표·링크 주소·진행 표시 줄은 빼고, 문장 단위로 끊어 읽어 중간에 멈추지 않게 합니다. 설정의 "답 읽어 주기" 스위치나 채팅의 "🔊 답 읽기" 단추로 켜고 끄며, 🎤·"산초야"로 물어본 질문의 답은 스위치가 꺼져 있어도 읽어 줍니다. 읽는 동안에는 호출 대기를 쉽니다(내 목소리를 호출어로 알아듣지 않게).
- **외부 목소리(TTS, 선택)**: 설정 › 목소리에서 키를 넣으면 답을 읽을 때 **외부 목소리를 먼저** 쓰고, 안 되면(키가 틀림·서비스 오류·연결 안 됨·재생이 막힘) **브라우저 목소리로** 읽습니다. OpenAI 호환 음성 API(`POST /v1/audio/speech`)이고, 키는 `data/settings.json` 에만 있으며 화면에는 `****` 로만 보입니다. 읽을 글이 그 서비스로 나가므로 **관리자만** 씁니다.
- **위쪽 표시**: 말하는 동안(그리고 듣는 동안) 헤더의 막대가 출렁입니다. 누르면 읽기를 멈추거나 듣기를 취소합니다. 폰에서는 위쪽 막 아래 가운데에 뜨고, "움직임 줄이기" 설정이면 출렁이지 않고 막대만 보입니다.

## 여러 사람이 쓰기 (설정 → 사용자)

같은 비서를 여러 사람이 씁니다. 관리자가 **설정 → 사용자**에서 계정을 추가하고(이름·아이디·임시 비밀번호·부서·역할 관리자/일반), 새 사용자는 **처음 로그인할 때 비밀번호를 바꿔야** 쓸 수 있습니다(바꾸기 전에는 서버가 다른 요청을 모두 막고, 바꾸면 그 사람의 다른 로그인은 풀립니다).

| | 사람마다 따로 (`data/users/<아이디>/`) | 함께 씀 |
|---|---|---|
| 자료 | 대화 기록(`chats/`) · 기억(`memory.md`) · 예약(`schedule.json`·`schedule-running.json`) · 일지(`journal/`) · 예약 결과 알림(그 사람에게만 보임) | 업무 데이터(`data/db/` 일정·프로젝트·할 일·메일정리) · WBS(`data/wbs/`) · 첨부(`uploads/`)·파일함 |

- **일반 사용자**는 설정(예시 데이터·권한 스위치·텔레그램)·사용자 관리가 화면에서 안 보이고, 서버도 막습니다(403). 대화·일정·프로젝트·WBS·메일정리·예약은 그대로 씁니다.
- **권한 스위치(연결된 앱·명령 실행·홈 폴더)와 텔레그램은 관리자의 비서에게만** 적용됩니다. 관리자의 Gmail·이 PC 를 일반 사용자의 비서가 열지 못하게 한 것입니다(일반 사용자의 메일정리는 늘 연습 모드).
- **비서도 남의 폴더를 못 엽니다.** 비서를 띄울 때마다 다른 사람의 개인 폴더(`users/<다른아이디>/**`)를 읽기·고치기 거절 목록에 넣습니다(진짜 claude 로 확인). 비서에게는 "이 사람의 개인 폴더"와 이름·부서·역할을 알려 줍니다(`templates/system-add/users.md`).
- 여러 사람이 쓰기 전의 `data/chats`·`memory.md`·`schedule.json`·`journal/` 은 서버를 켤 때 첫 관리자의 개인 폴더로 **옮겨집니다**(지우지 않고, 이미 있는 파일은 덮어쓰지 않음).
- 연습용 가상 사용자의 임시 비밀번호는 `data/임시비밀번호.txt` 에만 있습니다(git 에 안 올라가고 비서도 못 읽음).
- 아직 없는 것: 사용자 삭제·비밀번호 초기화·내 비밀번호 바꾸기 메뉴, 첨부(`uploads/`)·파일함·메일정리 자료의 사람별 분리.

## 메신저 (왼쪽 메뉴 "메신저", `public/m/messenger.html` · `data/db/channels.json` · `data/db/messages.json`)

왼쪽에 채널 목록(안 읽은 수), 가운데 대화, 아래 입력창(＋ 파일 첨부)이 있습니다. 새 메시지는 실시간(SSE)으로 나타납니다.

| 채널 | 누가 보나 | 누가 쓰나 |
|---|---|---|
| 📢 공지 (저절로 만들어짐) | 모두 | 관리자만 |
| 🏢 부서 (사람의 부서마다 저절로) | 부서가 같은 사람 | 같은 부서 |
| 📁 프로젝트 (관리자가 ＋ 새 채널에서 프로젝트·멤버를 골라 만듦) | 멤버 | 멤버 |
| 👤 1:1 (누구나 ＋ 새 채널에서) | 두 사람 | 두 사람 |

- **내가 속하지 않은 채널은 서버가 아예 보내지 않습니다.** 목록·메시지·첨부·실시간 연결 모두 멤버 확인을 거치고, 멤버가 아니면 "없는 채널"(404)로만 답해서 있는지도 알 수 없습니다(관리자도 마찬가지). 일반 업무 자료 주소(`/api/db/channels·messages`)는 막아 두었고, 첨부는 `data/메신저파일/<채널>/` 에 두고 채널 확인을 거치는 주소로만 내보냅니다. 비서(두뇌)도 이 파일들을 읽지 못합니다.

- 안 읽은 수는 사람마다 따로(`data/users/<아이디>/messenger-read.json`) 셉니다.
- 아직 없는 것: 채널 멤버 추가·빼기·채널 삭제, 메시지 고치기, 왼쪽 메뉴 "메신저"의 안 읽은 수 표시, 메시지가 아주 많아졌을 때의 나눠 저장(지금은 파일 하나).

## 회의록 (왼쪽 메뉴 "회의록", `public/m/meeting.html` · `data/db/rooms.json` · `data/db/meetings.json` · `docx.js`)

**위쪽: 회의실 주간 예약표** — 회의실 2개(`rooms.json` 의 대회의실·소회의실, 08:00~19:00), 30분 칸. 빈 칸을 누르면 예약하고, 같은 회의실·같은 시간이 겹치면 서버가 막습니다(409, 동시에 눌러도 한 명만). 예약은 **`data/db/bookings.json`** 에 따로 두고, 일정 목록에는 서버가 합쳐 보여 줘서 일정 메뉴·대시보드에도 나옵니다. 예약을 만들고·바꾸고·취소하는 길은 **회의록 메뉴의 예약표 하나뿐**입니다 — 일정 메뉴(일반 자료 주소)로는 예약을 끼워 넣거나 옮기거나 지울 수 없고(403), 비서도 예약 파일을 고치지 못하며, 일정 파일에 누가 `roomId` 를 붙여 넣어도 예약으로 치지 않습니다. 취소는 예약한 사람과 관리자만.

**아래: 회의 녹취 → 회의록**
1. **🎙 회의 녹취 시작**: 브라우저 음성 인식(Chrome·Edge, 한국어 `ko-KR`, 계속 받아쓰기·조용하면 저절로 다시 켬)이 말한 시각과 함께 화면에 쌓습니다. 일시정지·이어서·끝내기, 잘못 알아들은 줄은 눌러서 고치거나 지울 수 있고, 새로고침해도 받아쓴 글은 남아 있습니다. **음성 인식은 브라우저가 말소리를 구글·마이크로소프트 서버로 보내 글로 바꾸는 방식이라 회의 내용이 회사 밖으로 나갑니다** — 시작할 때 이 안내를 띄웁니다. 민감한 회의는 아래 붙여넣기를 쓰세요.
2. **📋 받아쓴 글 붙여넣기**: 마이크가 없거나 음성 인식이 안 되는 브라우저(그리고 다른 받아쓰기 앱의 글)도 같은 길로 정리합니다.
3. **끝내기 → 비서가 표로 정리**: 받아쓴 글(6만 자까지)이 서버로 가면 바로 "정리 중" 회의록이 저장되고(정리가 실패해도 원문은 안 잃음), 비서가 **도구 없이 그 글만 보고** 안건·논의·결정·할 일(담당·기한)을 JSON 으로 정리합니다. 서버가 모양을 검사해(아는 칸만·개수와 글자 수 제한·없는 날짜는 빈칸) `meetings.json` 에 저장하고, **워드 회의록**(`회의록_제목_날짜.docx`)을 `파일함/` 에 서버가 직접 만듭니다(파이썬·"명령 실행" 권한 필요 없음, 같은 이름이면 `-2`). **녹취 원문은 회의록에 붙여 보관**합니다.
4. **할 일은 물어본 뒤에만** `tasks` 에 등록합니다(정리가 끝나면 "할 일을 등록할까요?" 창이 뜨고, 이미 등록한 것은 다시 만들지 않음).

- 회의록·회의실 자료는 모두가 읽는 업무 자료이고, 고치기·지우기·할 일 등록·다시 정리는 만든 사람과 관리자만(일반 업무 자료 주소의 PUT·DELETE 는 403). 녹취 원문도 목록을 읽는 사람은 볼 수 있으니 민감한 회의는 올리지 마세요.
- 아직 없는 것: 회의실 추가·수정 화면(파일을 직접 고침), 참석자별 열람 제한, 회의록 수정(표 고치기), 반복 예약.

## 결재 (왼쪽 메뉴 "결재", `public/m/approval.html` · `data/db/approvals.json` · `data/결재파일/`)

**기안**: 오른쪽 위 "＋ 새 기안" → 제목 · 양식(일반 기안 / 구매 요청 / 출장) · 본문 · 금액(원) · 첨부(5개까지) · **결재선**(검토자 0~5명을 순서대로 → 마지막에 승인자 1명, 사용자 목록에서 고름). "저장"하면 **작성중**(나에게만 보임), "저장하고 올리기"(상신)하면 결재가 시작됩니다.

| 단계 | 누가 | 할 수 있는 것 | 결과 |
|---|---|---|---|
| 상신 | 기안자 | 올리기 (결재선이 이때 굳음) | 상태 **진행**, 첫 검토자에게 |
| 검토 | 검토자(순서대로, 지금 차례인 한 사람만) | 승인 / 반려(의견 필수) | 승인 → 다음 사람, 반려 → **반려** |
| 최종 | 승인자 | 승인 / 반려(의견 필수) / **전결** | 승인·전결 → **완료**, 반려 → **반려** |

- **반려되면 기안자에게 돌아갑니다.** 기안자가 의견을 보고 고쳐서 다시 올리면 2회차로 처음 검토자부터 새로 결재하고, 1회차의 서명·반려 의견은 기록에 그대로 남습니다.
- **전결**은 승인자만 누를 수 있고, 문서가 완료되는 것은 승인과 같지만 서명 칸과 인쇄 양식에 "전결"로 찍힙니다.
- **내가 결재할 차례인 문서**는 결재 화면 맨 위 "결재할 문서" 칸과 **대시보드의 "결재할 문서" 카드 숫자**에 나옵니다(서버가 셉니다). 누가 결재하면 열려 있는 화면이 바로 따라 바뀝니다.
- 승인·반려·전결·올리기·지우기는 누르면 **한 번 더 묻습니다**(서명은 되돌릴 수 없어서).

**서명 규칙 (서버가 확인)**

- 서명은 문서의 기록(`log`)에 한 줄씩 쌓이는 **승인·전결·반려·상신** 기록이고, **결재하는 본인의 로그인으로, 결재 주소(`/api/approvals/<id>/decide`)에서만, 그 사람의 차례일 때만** 서버가 덧붙입니다. 이름·부서·시각은 서버가 정하고(본문에 다른 이름·시각을 적어 보내도 무시), 같은 사람이 동시에 두 번 눌러도 한 번만 남습니다. 쌓인 줄은 어디서도 고치거나 지울 수 없습니다.
- **기안자가 문서를 고쳐도 서명 기록은 못 바꿉니다.** 고치는 길은 제목·양식·본문·금액·첨부·검토자·승인자 칸만 받고 서명·상태·결재선·단계·기안자는 본문에 있어도 버리며, 올린 뒤(진행·완료)에는 아예 못 고칩니다(반려된 문서만 다시 고칠 수 있음).
- 결재 문서는 일반 업무 자료 주소(`/api/db/approvals`)로 열리지 않고(404), 비서(두뇌)도 `db/approvals.json`·`결재파일/` 을 읽지도 쓰지도 못합니다.
- **보는 사람**: 작성중은 기안자만, 올린 뒤에는 기안자와 결재선에 든 사람만 봅니다. **관리자도 결재선에 없으면 못 봅니다**(없는 문서 404). 첨부도 같은 사람만 받습니다.

**인쇄 양식**: 문서를 열고 "🖨 인쇄 양식"을 누르면 A4 양식(제목·문서번호·결재란 표[기안·검토·승인의 이름과 서명 시각, 전결·반려 표시]·본문·첨부·결재 의견)이 뜨고, "인쇄"를 누른 뒤 **대상을 PDF 로 저장**으로 고르면 파일로 받을 수 있습니다. 결재가 끝나지 않은 문서는 양식 위에 "아직 결재가 끝나지 않은 문서" 표시가 붙습니다.

**비서에게 시키기**: 채팅에서 `기안서 써 줘: 비파괴검사 외주 420만 원, 다음 달 압력용기 개조 프로젝트` 처럼 말하면, 비서(approval 스킬)가 제목·양식·본문·금액만 정리한 초안 파일(`users/<아이디>/approval-draft.json`)을 놓고, 말이 끝나면 **서버가 검사해서 내 "작성중" 기안으로 만들고** 채팅에 알려 줍니다. **결재선을 고르고 올리는 일은 사람이** 합니다(비서가 초안에 결재선·서명을 끼워 넣어도 서버가 버립니다).

- 정한 것: 검토자에는 기안자 본인을 넣을 수 없습니다. 자기 문서를 직접 승인하는 것(기안자 = 승인자)은 **관리자(대표)만** 됩니다 — 일반 사용자는 다른 사람을 승인자로 골라야 합니다(7편 점검). 같은 사람을 결재선에 두 번 넣을 수 없습니다. 결재선은 올릴 때 사람의 고유 번호로 굳어서, 같은 아이디로 새로 만든 다른 사람이 차례를 이어받지 못합니다.
- 아직 없는 것: 올린 문서 회수(상신 취소)·합의·참조·후결·대리 결재, 결재선 저장, 차례가 왔다는 🔔 알림, 문서 검색, 지운 첨부 파일 정리(파일은 `결재파일/` 에 남음), 문서가 아주 많아졌을 때의 나눠 저장(지금은 파일 하나).

## 목표 (왼쪽 메뉴 "목표", `public/m/okr.html` · `public/m/okr-calc.js` · `data/db/okrs.json`)

**나무**: 분기를 고르면 **전사 → 부서 → 개인** 목표가 나무 모양으로 나오고, 목표마다 **핵심 결과(KR)** 표가 붙습니다. KR 은 지표 · 시작값 → 목표값 · 현재값 · 가중치(비율과 %) · 기한이고, 목표 줄에는 진척 막대(%)와 색 칩(순조·주의·위험)이 있습니다. 목표 줄의 ▾ 로 접고 펴고, "＋ 하위"로 아래 수준 목표를 만들고, "수정"에서 제목·담당·부서·메모·상위 목표·KR 들을 고치거나 지웁니다(지우기는 한 번 더 묻고, 하위 목표가 있으면 지울 수 없음). **KR 의 "현재값" 칸은 숫자를 고치고 Enter 만 치면 바로 저장**되어 위 목표들의 진척이 따라 바뀝니다.

**계산 규칙** (화면과 점검이 같은 파일 `okr-calc.js` 를 씁니다)

| 무엇 | 어떻게 |
|---|---|
| KR 달성률 | (현재값 − 시작값) ÷ (목표값 − 시작값), 0~100% 로 자름. **불량률처럼 낮출수록 좋은 지표**는 시작값(예 3)을 목표값(예 1)보다 크게 적으면 저절로 "내려갈수록 달성"(현재 1.8 → 60%). 시작값을 비우면 0 |
| 목표 진척 | KR 달성률의 **가중 평균**(가중치 ÷ 가중치 합, 합이 100 이 아니어도 됨. 가중치를 비우면 1) |
| 상위 목표 | **하위 목표들의 평균**(전사 = 부서들의 평균, 부서 = 개인들의 평균). 상위 목표가 자기 KR 도 가지면 그것도 하위 목표 하나처럼 한 몫으로 함께 평균 |
| 색 | 진척을 "시간이 지난 만큼 가야 하는 진척"(분기 시작~끝 중 오늘까지 지난 비율, 막대 위 검은 눈금)과 견줍니다. 뒤처짐 10%p 이내 **순조**, 25%p 이내 **주의**, 넘으면 **위험**. 100% 면 늘 순조, KR 은 기한 기준이고 **기한이 지났는데 미달이면 위험**. 분기 첫 주에는 0% 라도 순조(아직 시간이 안 지났으니) |
| KR 이 없음 | 진척을 계산하지 않고 "KR 없음"(0% 로 꾸미지 않음). 형식이 틀린 KR·목표는 계산에서 빼고 화면 위에 이유를 알려 줌 |

**저장**: 목표 하나 = `okrs.json` 의 항목 하나(`id`·`level`·`parentId`·`title`·`owner`·`dept`·`quarter`('2026-Q4', 연간은 '2026')·`note`·`krs`)인 평평한 목록이라 다른 업무 자료(일정·프로젝트)와 같은 저장소(`/api/db/okrs`)와 실시간 반영을 씁니다. 상위 목표는 같은 분기의 더 높은 수준만 고를 수 있습니다.

**비서에게 시키기** (`okr` 스킬)
- `이번 분기 품질팀 OKR 초안 짜 줘` → 그 분기의 부서 목표 1~2개와 KR 3개씩을 `okrs.json` 에 덧붙입니다. 같은 분기에 전사 목표가 있으면 거기에 잇고(없으면 **새로 만들지 않고** 안내), 말하지 않은 시작값·목표값은 "제안"이라고 메모에 밝힙니다. 현재값은 시작값과 같게(진척 0).
- `불량률 KR 현재값 1.8로` → 그 KR 의 현재값만 바꾸고 달성률을 알려 줍니다(같은 지표가 여럿이면 먼저 묻고, 단위가 다르게 들려도 먼저 묻습니다).
- 진척·색은 파일에 적지 않습니다(화면이 계산). 목표·KR 을 지우기 전에는 먼저 묻습니다.

- 정한 것: 목표는 모두가 읽고 고치는 업무 자료입니다(일정·프로젝트와 같음) — 담당자만 고치게 하는 제한은 아직 없습니다.
- 아직 없는 것: 목표별 체크인(주간 기록)·진척 이력 그래프, 담당자만 고치기, KR 별 가중치 합 100 강제, 지난 분기 목표 복사, 대시보드 카드.

## 공수 (왼쪽 메뉴 "공수", `public/m/manday.html` · `public/m/manday-calc.js` · `xlsx.js` · `data/db/mandays.json`)

**입력은 한 줄 붙여넣기**: 위 칸에 `10/6 열교환기 용접 8h, 야근 2h / 압력용기 도면검토 3h` 처럼 붙여 넣고 **"비서가 정리하기"**를 누르면, 비서가 글을 **날짜·프로젝트·작업·시간(야근 여부)** 한 줄씩으로 나눠 "정리 결과" 표로 보여 줍니다(날짜 하나 뒤에 `,` 나 `/` 로 이어진 일은 모두 그 날짜, "야근 2h" 는 바로 앞 일의 야근 시간, "30분"·"반나절" 같은 말도 읽음). **맞는지 확인하고 [저장]을 눌러야** 내 기록이 됩니다 — 표의 날짜·프로젝트·작업·시간·야근은 저장 전에 고칠 수 있고, 붙여넣지 않고 "＋ 직접 줄 추가"로 한 줄씩 적어도 됩니다.

**프로젝트는 projects 와 맞추고, 모르면 물어봅니다.** 서버가 비서의 답과 상관없이 글의 프로젝트 이름을 프로젝트 목록과 다시 맞춰 보고, **하나로 안 정해지면**(예: "압력용기"가 "압력용기 개조 · 사아자에너지"와 "압력용기 개조 · 가나다전자" 둘과 맞음 — 비서가 하나를 골랐어도 믿지 않음) 그 줄을 주황색 "❓ 골라 주세요"로 두고 후보를 먼저 보여 줍니다. 목록에 없는 이름은 "목록에 없어요 — 고르거나 기타 업무로"라고 묻습니다. 프로젝트 없는 일은 "기타 업무". 모든 줄이 풀려야 저장 단추가 켜집니다.

**내 기록 · 합계**
- **내 기록 표**: 월을 고르면 그 달의 날짜·프로젝트·작업·시간·M/D·야근 표시, 맨 아래 합계. 잘못 들어간 줄은 ✕ → "지울까요?"에서 지웁니다. 방금 저장한 줄은 잠깐 연두색.
- **월별 합계 / 프로젝트별 합계**: 시간 · 야근 시간 · **M/D(1 M/D = 8시간)**. 월별은 세로 막대그래프(막대를 누르면 그 달로), 프로젝트별(고른 달 기준)은 가로 막대. 야근 시간도 시간에 더하고 야근만 따로도 보여 줍니다. 이름이 같은 프로젝트는 고객사를 붙여 구분합니다.
- **📥 엑셀 내보내기**: 내 기록 시트("공수 기록": 날짜·프로젝트·작업·시간·야근·M/D + 합계 줄)와 "월별·프로젝트별 합계" 시트가 든 `.xlsx` (고른 달만, 또는 전체 기간). 외부 패키지 없이 서버가 직접 만듭니다(`xlsx.js`).
- **WBS 화면의 "투입 공수"**: 프로젝트 → WBS 화면 위 카드 줄에 그 프로젝트에 **모든 사람이 쓴 시간의 합**(예: `14h · 1.75 M/D · 야근 2h · 기록 3건 · 2명`)이 나옵니다. 공수 기록이 바뀌면 바로 따라 바뀝니다. **읽기 전용 공유 링크 화면에는 나오지 않습니다**(로그인 없이는 읽지 못함).

**누가 무엇을 보나**: "내 기록"은 **그 사람만** 봅니다 — 일반 업무 자료 주소(`/api/db/mandays`)로는 열리지 않고(404), **관리자도 남의 기록은 못 보며**(남의 기록을 지우는 것도 "없는 기록" 404), 비서(두뇌)도 `db/mandays.json` 을 읽지도 쓰지도 못합니다. WBS 의 합계 숫자만 모든 사람의 시간을 더해 내보내고 누가 얼마를 썼는지는 담기지 않습니다.

**서버가 지키는 규칙**: 한 줄은 날짜(내일까지, 400일 이내)·작업(60자)·시간(0보다 크고 24 이하, 0.25시간=15분 단위), 프로젝트는 목록에 있는 것이거나 "기타 업무". **한 사람의 하루는 합쳐서 24시간까지**이고, 똑같은 줄(날짜·프로젝트·작업·시간·야근)은 두 번 저장되지 않고 건너뜁니다. 한 줄이라도 틀리면 **아무것도 저장하지 않습니다**. 기록한 사람·이름·id·저장 시각은 서버가 정하고(보낸 값 무시), 비서에게는 도구 없이 글과 프로젝트 목록만 건네며 대화 기록도 남기지 않습니다(`--no-session-persistence`). 붙여넣은 글은 비서(Claude)에게 건네지므로 민감한 내용은 적지 마세요.

- 정한 것: 야근 시간은 시간(과 M/D)에 그대로 더합니다(가산 없음). 저장한 기록을 고치는 화면은 아직 없어서 틀리면 지우고 다시 넣습니다.
- 아직 없는 것: 기록 수정, 팀·부서 단위 합계(관리자 보기), 주간 달력 입력, 프로젝트 예산 대비 공수, 비서에게 채팅으로 "공수 입력해 줘"(공수 메뉴 붙여넣기로 안내함).

## 파일 첨부와 문서 만들기 (채팅)

- 문서 만드는 요령은 스킬 `data/.claude/skills/office-docs/SKILL.md`(원본 `templates/skills/office-docs/`)에 있습니다. 파이썬(`python`, `python3` 는 이 PC 에서 멈춤)으로 openpyxl·python-docx 를 쓰고, **python-pptx 는 이 PC 에 없어서** PPT 는 설치 방법만 안내합니다(마음대로 설치하지 않음).
- 파이썬을 실행해야 하므로 **설정 → 권한 → 명령 실행**이 켜져 있어야 문서를 만들 수 있습니다.

## 메일정리 (왼쪽 메뉴 "메일정리", `data/db/mails.json`)

"✳ 메일 정리하기"를 누르면 비서가 최근 2일 받은 메일을 읽고 **긴급·업무·광고**로 나눠 요약 한 줄·할 일·마감일을 `mails.json` 에 적습니다. 카드를 누르면 오른쪽에 자세히와 단추(답장 초안 만들기 · 일정으로 등록 · 할 일로 등록 · 처리됨)가 뜹니다.

- **연결된 앱 스위치가 꺼져 있으면 연습 모드**: 실제 메일함 대신 가상 회사 "가나다전자"의 연습용 메일 8통(`data/db/sample-mails.json`, 서버를 켜면 `templates/sample-mails.json` 에서 한 번 복사)을 읽습니다. 켜져 있으면 내 Gmail 의 받은편지함을 읽습니다.
- **원문은 저장하지 않고 요약만** 저장합니다. 비서가 원문 칸을 끼워 넣거나 긴 글을 적어도 서버가 아는 칸만 남기고 글자 수를 잘라 냅니다. 비서가 지워 버린 기존 항목(처리됨 표시 등)은 되살립니다.
- 답장 초안은 **보내지 않습니다.** 연습 모드는 화면에만 저장하고, 실제 모드는 Gmail 임시보관함에 넣기만 합니다(`create_draft`).
- 일정·할 일 등록은 비서 없이 화면이 바로 합니다. 메일이 알리는 일정(회의 날짜·시각·장소)이 있으면 그 날 그 시각에, 없으면 마감일에 종일 일정으로 들어갑니다.

## 권한 (설정 → 권한)

비서는 처음에 파일 읽기·쓰기(data/ 안)와 웹 검색만 합니다. 아래 스위치를 **주인이 직접** 켜야 더 할 수 있고(`data/settings.json`, 비서는 읽지 못함), 켜진 권한은 채팅 입력창 왼쪽에 작게 보입니다.

| 스위치 | 켜면 |
|---|---|
| 연결된 앱 | Gmail·캘린더·드라이브 도구(`mcp__claude_ai_…`)를 읽기·초안·만들기까지 쓴다. 지우기·공유·덮어쓰기는 늘 막힘. **메일 보내기는 비서가 "보낼까요?"라고 묻고 내가 "네"라고 한 바로 그 차례에만** 열리고, 예약 실행에서는 늘 막힘 |
| 명령 실행 | Bash(윈도우는 PowerShell도). 비밀 파일·`claude` 이름이 든 명령은 막지만, 켜져 있는 동안은 사실상 무엇이든 할 수 있음 → 필요할 때만 켜기. 예약·메일정리(주인이 안 보는 실행)와 자기 수정 차례에는 주지 않음. 8편 안전장치를 우회할 수 있다 → 아래 "명령 실행을 켰을 때의 한계" |
| 내 홈 폴더 읽기 | `--add-dir` 로 홈 폴더를 읽기 전용으로 연다. `.ssh`·`.aws`·`.claude`·`AppData` 등은 늘 막힘 |
| 자기 수정 | 비서가 이 앱의 코드 폴더를 고친다 (관리자만·기본 꺼짐). 아래 "8편 안전장치"의 관문을 통과해야 반영됨. 켜져 있는 동안은 "명령 실행"이 비서에게 주어지지 않음 |

**5편 점검에서 더 조인 것** (진짜 claude 로 확인한 구멍을 막음)

- 메일 보내기: "보낼까요?"→"네" 차례에 서버가 claude 의 PreToolUse 훅으로 문지기(`mailgate.js`)를 건다. **보여 준 주소로, 한 통만** 통과하고 나머지는 보내기 직전에 막힌다. 구글 캘린더 만들기·고치기(초대 메일이 나감)도 "등록할까요?"→"네" 뒤에만.
- 작업 폴더의 `CLAUDE.local.md`(숨은 지침으로 실림)·`.claude/settings*.json`(훅·허용 규칙이 실림)·`.mcp.json` 은 비서가 쓸 수 없고, 생겨 있으면 실행 직전에 이름을 바꿔 꺼 두고 알림을 남긴다. 훅은 늘 끈다.
- 받기 주소는 그 폴더 안의 보통 파일만 내보낸다 (하드·심볼릭 링크, 폴더 바꿔치기(정션) 거절).
- 비서가 띄운 프로그램(멈춘 파이썬 등)이 남아도 채팅이 멈추지 않는다.
- 두뇌는 따로 API 키를 사지 않고, 이 PC 에 로그인한 Claude Code 를 그대로 씁니다.

## 8편 안전장치 — 비서가 코드를 고쳐도 앱이 망가지지 않게 (`guard.js` · `supervisor.js` · `start.bat`)

**한 줄 요약**: 비서가 "검사하고 나서 켜야지" 하고 절차를 지켜 주길 기대하지 않는다. **서버와 감시자가 직접 검사하고, 통과하지 못하면 막거나 되돌린다.** 그 검사를 하는 파일들은 비서가 고칠 수 없다(= 불변 층).

### 한눈에

```
 사람: start.bat 더블클릭
          │
          ▼
 감시자 supervisor.js ─────────── 서버가 죽으면: ① 지금 코드·변경을 rescue/<시각> 브랜치에 보존
          │ 서버를 켜고 지켜봄                    ② 마지막 정상 버전(last-good)으로 되돌림 ③ 다시 켬
          │ (/health 로 건강 검사)               세 번 연속 실패하면 멈추고 오류를 보여 줌
          ▼
 서버 server.js
          │
          ├─ 설정 › "서버 다시 시작" 단추 ─┐
          │                                ├─▶ 관문 guard.js:  ① 불변 파일이 그대로인가  ② 문법 검사
          └─ 채팅 + "자기 수정" 스위치 ─────┘                    ③ selftest 전체        ④ 검사 중 코드가 안 바뀌었나
                                                  모두 통과 → (자기 수정이면 커밋) → 재시작
                                                  하나라도 실패 → 재시작 거부(서버는 그대로) / 자기 수정은 보존 후 되돌림
```

### 다섯 가지 장치

| 장치 | 쉬운 설명 | 어디서 보나 |
|---|---|---|
| **관문** | 서버를 다시 켜기 전에 서버가 직접 ①~④를 돌려 본다(몇 분 걸림). **하나라도 실패하면 다시 켜지 않고 이유를 알려 주며, 지금 서버는 그대로 둔다.** 같은 앱 폴더의 관문은 한 번에 하나만 돈다(서버와 감시자 사이도 파일 잠금으로) | 설정 › 서버 다시 시작 (`POST /api/restart`, 관리자만) |
| **건강 검사** | 서버가 "살아 있고 데이터 폴더를 읽을 수 있는지" 대답한다. 로그인 없이 `{ok, pid, uptimeSec}`, 못 읽으면 503 | `http://127.0.0.1:8790/health` |
| **last-good** | "마지막으로 정상이었던 버전"에 붙이는 git 태그. 감시자가 ① 서버를 켜서 **30초 동안 계속 건강**하고 ② 작업 폴더가 **깨끗**(커밋 안 한 변경 없음)하고 ③ 불변 파일이 그대로이고 ④ **감시자가 직접 돌린 관문(문법 검사·selftest)도 통과**했을 때만 붙인다. 서버(비서가 고칠 수 있는 파일)가 "통과했다"고 하는 말은 믿지 않는다. 원격(GitHub)에는 올리지 않는다 | `git tag -l last-good` · `data/logs/supervisor.log` |
| **감시자** | `start.bat` 이 켜는 `supervisor.js`. 서버가 비정상으로 끝나면 보존 → last-good 으로 되돌림 → 다시 켬. 되돌린 사실은 🔔 알림으로 남는다. **세 번 연속 실패하면 멈추고** 마지막 오류를 창에 보여 준다. 켜기 전에 `server.js` 문법 검사를 한 번 더 하므로, 문법이 깨진 `server.js` 는 아예 켜지 않는다 | `Sancho server` 창 · `data/logs/supervisor.log` · 🔔 |
| **불변 층** | 비서가 절대 못 고치는 파일: `start.bat` · `supervisor.js` · `guard.js` · `selftest.js` · `mailgate.js`(메일 발송 문지기) · `test/`. 그리고 어느 폴더에 있든 `.git` · `.gitignore` · `.gitattributes` · `.gitmodules` · `CLAUDE.md` · `CLAUDE.local.md` · `.claude` · `.mcp.json`. 권한 규칙으로 막고(1차), 그래도 바뀌면 서버가 git 으로 바뀐 파일을 보고(2차), 관문과 감시자가 last-good 과 비교해(3차) 잡는다 | `guard.js` 의 `IMMUTABLE`·`OFF_LIMITS`·`ANYWHERE` |

감시자가 보는 서버의 종료 코드: `0` 정상 종료(감시도 끝, Ctrl+C 포함) · `10` 관문을 통과한 재시작 요청(바로 다시 켬) · `11` 포트를 이미 누가 씀(되돌리지 않고 멈춤) · 그 밖 = 비정상(되돌리고 다시 켬, 연속 실패로 셈).

### 자기 수정 스위치 (설정 › 권한 › "자기 수정", 관리자만·기본 꺼짐)

켜면 관리자의 비서가 이 앱의 코드(화면·서버)를 직접 고칠 수 있다. 채팅으로 "보내기 버튼을 둥글게 바꿔" 처럼 부탁하면 된다.

1. **열어 주는 조건**: 서버가 `start.bat`(감시자)로 켜져 있고, 앱 폴더에 **커밋 안 한 변경이 없을 때**만. 아니면 폴더를 열지 않고 비서가 이유를 말해 준다. (되돌릴 때 사람이 하던 작업까지 지우지 않으려고)
2. **고칠 때**: 비서의 실행에 앱 폴더 읽기·쓰기 허용(`--add-dir`)이 붙고, 불변 층은 거부 규칙으로 빠진다. 지침에 "앱 코드는 고치기만 하고 커밋·재시작은 하지 마라"가 들어간다. 이 차례에는 "명령 실행"을 켜 두었어도 비서에게 주지 않는다.
3. **답이 끝나면 서버가**: 바뀐 파일 확인 → 불변 층을 건드렸으면 거부 → 관문 → 통과하면 **커밋("자기 수정: 요청 내용", 작성자 Sancho 비서)** → 재시작 → 화면이 저절로 새로 고쳐진다.
4. **실패하면**: 비서가 고친 것을 `rescue/selfmod-<시각>` 브랜치에 **남겨 둔 뒤** 앱 폴더를 원래대로 되돌리고, 이유를 채팅에 보여 준다. 서버는 그대로 켜져 있다.
5. **기록**: 설정 › 자기 수정 기록(시각·요청·결과·커밋·보존 브랜치). 파일은 `data/selfmod-log.json`.

### 자주 하는 일

| 하고 싶은 것 | 방법 |
|---|---|
| 서버 켜기 / 끄기 | `start.bat` 더블클릭 / `Sancho server` 창에서 Ctrl+C (정상 종료로 처리되어 되돌리지 않음) |
| 사람이 코드를 고친 뒤 반영 | `node selftest.js` → 커밋 → 설정 › 서버 다시 시작 (또는 창을 닫고 `start.bat`) |
| **불변 파일을 사람이 고쳤을 때** | 감시자는 last-good 을 자동으로 올리지 않고, 관문도 "고칠 수 없는 파일이 달라요"로 막는다. `node selftest.js` 통과 → 커밋 → 직접 `git tag -f last-good` |
| 되돌려진 변경 살펴보기 | `git branch --list "rescue/*"` → `git diff last-good rescue/<이름>` |
| 그중 파일 하나만 꺼내 오기 | `git checkout rescue/<이름> -- <파일>` (꺼낸 뒤 검사·커밋) |
| 보존본이 필요 없을 때 | `git branch -D rescue/<이름>` |

### 명령 실행을 켰을 때의 한계 (중요)

"명령 실행"(설정 › 권한)을 켜면 비서가 이 PC 에서 명령(PowerShell·Bash)을 돌릴 수 있다. **명령은 파일 권한 규칙을 거치지 않으므로, 위의 안전장치 중 "막기"는 사실상 없어지고 "알아채기"만 남는다.**

- **불변 층을 직접 고칠 수 있다**: 권한 규칙(Edit·Write 거부)은 파일 도구에만 걸린다. 명령으로는 `start.bat`·`guard.js`·`selftest.js` 도 고칠 수 있다.
- **git 도 다룰 수 있다**: 커밋·`git tag -f last-good`·브랜치 지우기·`reset` 을 할 수 있다. 관문과 감시자는 "last-good 과 비교"해서 알아채는데, 그 기준(last-good)까지 옮기면 알아채지 못한다.
- **비밀 파일·설정을 우회해 볼 수 있다**: 서버는 비밀 파일 이름(`users.json`·`settings.json` 등)과 `claude` 가 **그대로 적힌** 명령만 막는다. 이름을 돌려 쓰는 꼼수(변수로 이어 붙이기 등)까지는 못 막는다. 권한 스위치가 든 `settings.json` 을 고치거나, 감시자·서버 프로세스를 끄는 것도 가능하다.
- **밖으로 보내기도 막지 못한다**: 명령으로 인터넷에 자료를 보낼 수 있다(청사진의 "회사 밖으로 자료 전송 금지"를 장치로는 지키지 못함).
- **그래도 남는 것**: 주인이 보지 않는 실행(예약·메일정리)과 **자기 수정 차례에는 명령 도구를 아예 주지 않는다.** 명령으로 앱 폴더를 고치면 폴더가 "깨끗하지 않음"이 되어 자기 수정이 멈추고, 감시자도 last-good 을 올리지 않는다. 감시자 코드가 바뀌어도 다음에 `start.bat` 을 켤 때까지는 지금 돌고 있는 감시자가 그대로 지킨다.
- **그래서**: 명령 실행은 꼭 필요할 때만 잠깐 켜고, "연결된 앱"과 함께 켜 두지 않는다(메일 속 지시가 명령으로 이어질 수 있음). 끈 뒤에는 `git status` · `git log -3` · `git tag -l last-good` 로 모르는 변경이 없는지 확인한다.

### 그 밖의 한계

- 사람이 앱 폴더를 고치는 **도중에** 자기 수정이 실패해 되돌리면, 그사이 사람이 바꾼 것도 같이 되돌려질 수 있다(보존 브랜치에는 남는다). 자기 수정을 쓸 때는 앱 폴더를 손대지 않는다.
- 비서가 `server.js` 에서 관문을 부르는 줄을 지우면 재시작 단추가 사라진다. 그래도 감시자가 켤 때마다 문법을 보고, last-good 은 감시자가 직접 돌린 관문을 통과해야만 올라간다.
- 개발 중 주의: 커밋 안 한 작업이 있는데 서버가 죽으면 그 작업은 사라지지 않고 `rescue/<시각>` 브랜치로 옮겨지며, 작업 폴더는 last-good 으로 돌아간다.
- 되돌린 파일은 이 PC 의 git 설정(`core.autocrlf`)에 따라 윈도우 줄바꿈으로 다시 써질 수 있다. 내용(git 기준)은 같다.
