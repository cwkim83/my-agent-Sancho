# 업무 데이터 규칙 (platform)

대시보드와 일정 화면은 `data/db/` 의 JSON 파일을 그대로 읽는다. 파일을 고치면 열려 있는 화면이 바로 따라 바뀐다.
그래서 형식이 틀리면 화면이 깨진다. 아래 형식을 정확히 지킨다.

## 파일 위치와 필드

파일마다 `[ {…}, {…} ]` 모양의 JSON 배열이고, 항목 하나가 일정(할 일, 프로젝트) 하나다. 들여쓰기는 2칸.
날짜는 `YYYY-MM-DD`, 시각은 24시간 `HH:MM` (한 자리 시는 `09:00` 처럼 0 을 붙인다). 값이 없으면 빈 글자 `""`, 프로젝트 연결만 `null`.

### 일정 — `data/db/events.json`

| 필드 | 뜻 |
|---|---|
| `id` | 항목 번호 (새로 만들 때 짧은 무작위 글자, 아래 규칙) |
| `title` | 제목 |
| `kind` | `회의` · `출장` · `검사 입회` · `개인` 중 하나 (수압시험·검사에 입회하면 `검사 입회`) |
| `date` | 시작 날짜 |
| `endDate` | 끝 날짜. 하루짜리면 `date` 와 같게 |
| `start` | 시작 시각. 종일이면 `""` |
| `end` | 끝 시각. 종일이면 `""` |
| `place` | 장소 |
| `memo` | 메모 |
| `projectId` | 연결된 프로젝트의 `id`. 확실하지 않으면 `null` |

### 회의실 예약 — `data/db/bookings.json` (읽기만 한다. 고칠 수 없다)

일정과 같은 칸(`id`·`title`·`date`·`start`·`end`·`place`…)에 `roomId`(회의실)·`bookedBy`(예약한 사람 아이디)·`bookedByName` 이 더 있다. 화면의 일정 목록에는 함께 보이니, 오늘 일정을 말할 때는 이 파일도 같이 읽는다.
회의실 예약·시간 바꾸기·취소는 서버가 겹침을 막아야 해서 주인이 **회의록 메뉴의 회의실 예약표**에서 직접 한다고 안내한다. `events.json` 에 `roomId` 를 붙여 예약을 흉내 내지 않는다.

### 할 일 — `data/db/tasks.json`

| 필드 | 뜻 |
|---|---|
| `id` | 항목 번호 |
| `title` | 할 일 |
| `projectId` | 연결된 프로젝트의 `id`, 없으면 `null` |
| `due` | 마감 날짜 |
| `status` | `할 일` · `진행중` · `완료` 중 하나. 끝냈으면 `완료` (`done` 같은 다른 필드는 없다) |
| `owner` | 담당자 이름 |

### 프로젝트 — `data/db/projects.json`

| 필드 | 뜻 |
|---|---|
| `id` | 항목 번호 |
| `name` | 프로젝트 이름 |
| `client` | 고객사 |
| `status` | `계획` · `진행중` · `완료` 중 하나 |
| `progress` | 진행률, 0~100 숫자 |
| `start` | 시작 날짜 |
| `due` | 납기 날짜 |
| `owner` | 담당자 이름 |

### 알림 — `data/db/notices.json` (읽기만 한다. 아직 직접 고치지 않는다)

`id`, `title`, `body`, `level`(`안내` · `주의`), `at`(만든 시각), `read`(읽었으면 `true`), `detail`(선택: 눌렀을 때 보이는 결과 전체. 예약 결과 알림에만 있다).

### WBS 공정표 — `data/wbs/<프로젝트 id>.json`

WBS 공정표를 짜거나 고치는 요청("WBS 짜 줘: …", "○○ 진도율 60%로")은 이 문서가 아니라 **wbs 스킬**(`.claude/skills/wbs/SKILL.md`)의 형식과 순서를 따른다. 그때도 프로젝트 목록(위 `projects.json` 표)·`id` 만드는 법·날짜 계산법·지우기 규칙은 이 문서를 따른다.

## 고치는 순서

1. 고칠 파일을 먼저 읽는다. 파일이 아직 없으면 `[]` 로 새로 만든다.
2. 바꿀 항목 하나만 고친다. 새 항목은 배열 맨 끝에 덧붙이고, 나머지 항목은 한 글자도 바꾸지 않는다.
3. 고친 뒤 파일을 다시 읽어 JSON 이 올바른지(쉼표·따옴표·대괄호) 확인한다. 틀렸으면 바로 바로잡는다.
4. 무엇을 바꿨는지 한 줄로 알린다. 예: `일정 추가: 10/7(수) 15:00~16:00 열교환기 수압시험 입회 (2공장)`

규칙:
- 새 항목의 `id` 는 짧은 무작위 글자(영문 소문자·숫자 8자, 예: `k3f9a2xq`)로 만든다. 그 파일에 이미 있는 `id` 와 겹치면 다시 만든다. 고칠 때는 `id` 를 그대로 둔다.
- 지우는 일은 먼저 물어보고, 허락받은 뒤에만 한다. 애매하면 지우지 않는다.
- "그 일정"처럼 가리키는 말은 방금 대화에서 다룬 항목이다. 후보가 여럿이거나 확실하지 않으면 파일을 읽어 후보를 말하고 어느 것인지 물어본다.
- 말하지 않은 값은 지어내지 않는다. 다만 일정의 끝 시각은 시작 시각의 1시간 뒤로 하고, 그렇게 했다고 알린다. 장소·메모를 모르면 `""`.
- 일정을 미룰 때는 길이를 유지한다. 시작이 한 시간 밀리면 끝도 한 시간 민다.
- 프로젝트 이름이 분명히 맞을 때만 `projectId` 를 넣는다 (`data/db/projects.json` 에서 찾는다).

## 날짜·시각 계산

오늘 날짜(요일 포함)는 실행할 때마다 따로 알려 준다. 모든 날짜 말은 그 날짜를 기준으로 **정확히** 계산한다. 어림짐작하지 않는다.

- 한 주는 **월요일부터 일요일**이다. 요일 번호는 월 1 · 화 2 · 수 3 · 목 4 · 금 5 · 토 6 · 일 7.
- `내일` = 오늘 + 1일, `모레` = 오늘 + 2일.
- `이번 주 ○요일` = (오늘이 속한 주의 월요일) + (○ 번호 − 1)일.
- `다음 주 ○요일` = (오늘이 속한 주의 월요일) + 7 + (○ 번호 − 1)일. 
- 그냥 `○요일` 이면 오늘 이후(오늘 포함) 가장 가까운 그 요일이다.
- 월말을 넘기면 달이 바뀐다: 1·3·5·7·8·10·12월은 31일까지, 4·6·9·11월은 30일까지, 2월은 28일(윤년 29일)까지.
- 예: 오늘이 2026-10-06(화)이면 이번 주 월요일은 10-05, 내일은 2026-10-07(수), 이번 주 금요일은 10-09, 다음 주 화요일은 2026-10-13.
- 계산한 날짜는 요일과 함께 답에 적어(예: `10/7(수)`) 주인이 맞는지 바로 볼 수 있게 한다.

시각 말: `오후 세 시` → `15:00`, `오전 9시 반` → `09:30`, `낮 12시` → `12:00`, `밤 12시` → `00:00`, `저녁 6시` → `18:00`.
